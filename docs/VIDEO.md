# 웨딩 플레이리스트 영상 만들기

청첩장 사진으로 유튜브 플레이리스트 스타일 영상을 만들고 MP4로 뽑는 도구입니다.

화면 구성은 **3분할**입니다.

```
┌──────────┬────────────────┬──────────┐
│          │      ◯         │          │
│  사진    │   회전하는 LP   │  사진    │   ← 좌우는 사진 순서대로 크로스페이드
│  (짝수)  │   (고정 사진)   │  (홀수)  │
│          │                │          │
├──────────┴────────────────┴──────────┤
│            흘러가는 가사 자막          │
└──────────────────────────────────────┘
```

- 중앙: 고른 사진 한 장이 원 전체를 채우고 시계 방향으로 천천히 회전 (은/금 톤암 포함)
- 좌우: 사진 목록을 짝/홀로 나눠 갖고 번갈아 크로스페이드 — 한 번에 한쪽만 바뀌어 차분합니다
- 하단: `.lrc` 자막이 음악에 맞춰 흐르고, 단어별 하이라이트(가라오케)도 됩니다
- 그 밖에: 블러 배경, 보케, 광선 누출, 필름 그레인, 진행 바, 인트로/아웃트로 타이틀

---

## 구조

핵심은 **렌더 엔진 하나를 웹과 CLI가 공유**한다는 점입니다.

```
src/video/engine/        ← 순수 캔버스 렌더 엔진 (DOM·Math.random 미사용)
   drawFrame.js            프레임 합성 진입점: drawFrame(ctx, scene, env, t)
   timeline.js             사진 슬롯 / 좌우 컬럼 타임라인 계산
   lrc.js                  LRC 자막 파서
   config.js               프로젝트 스키마 + 기본값
   layers/                 background · splitColumns · vinyl · lyrics · overlays

src/video/studio/        ← 웹 디자이너 (#/studio)
tools/video/render.mjs   ← Node MP4 렌더러
```

엔진은 `drawFrame(ctx, scene, env, t)` 하나로 호출됩니다. 같은 `(scene, t)`면 항상 같은 픽셀이
나오도록 만들어져 있어서(시드 기반 난수, 시간 기반 애니메이션만 사용) **스튜디오 미리보기가
곧 최종 mp4**입니다.

`env`만 환경별로 다릅니다.

| | 브라우저 | Node |
|---|---|---|
| 캔버스 | `document.createElement('canvas')` | `@napi-rs/canvas` |
| 이미지 | `new Image()` | `loadImage()` |
| 폰트 | index.html의 Google Fonts | `assets/fonts/*.ttf` 등록 |

## 1. 웹 디자이너로 구성 잡기

```bash
npm run dev
```

브라우저에서 **http://localhost:5173/Wedding/#/studio**

| 탭 | 하는 일 |
|---|---|
| 출력 | 해상도(가로/세로/정사각), fps, 음원, 페이드, 영상 길이 |
| 사진 | 사진 추가·삭제·순서 변경, 장당 노출 시간, 세로 크롭 위치 |
| LP | 원에 넣을 **고정 사진** 고르기, 회전 속도, 크기·위치, 톤암 |
| 3분할 | 중앙 컬럼 폭, 경계선, 좌우 밝기, 켄번즈 |
| 배경 | 블러·밝기·채도·틴트·비네트 |
| 가사 | `.lrc` 불러오기 / 타이밍 잡기 / 내보내기 |
| 자막 스타일 | 글자 크기·위치·색·애니메이션·가라오케 |
| 타이틀 | 인트로/아웃트로 문구 |
| 효과 | 보케, 광선 누출, 그레인, 진행 바, 레터박스, 테마 색 |

- `Space` = 재생/정지. 재생 위치는 오디오가 기준이라 자막 타이밍이 정확합니다.
- 편집 내용은 localStorage에 자동 저장됩니다.
- 다 됐으면 우측 상단 **프로젝트 내보내기** → `video.project.json` 을 **저장소 루트**에 놓습니다.

## 2. 가사 자막 넣기

> ⚠️ 이 저장소에는 가사 텍스트를 커밋하지 않습니다. 직접 준비한 `.lrc`를 쓰세요.
> 영상을 공개 배포할 계획이라면 음원·가사의 이용 권리를 먼저 확인하시기 바랍니다.

`public/video/lyrics/sample.lrc` 가 문법 예시가 들어간 빈 템플릿입니다. 복사해서 채우세요.

```lrc
[00:12.40]가사 한 줄
[00:18.90]다음 줄
[00:24.00]                     ← 텍스트 없는 줄 = 간주 (음표 인디케이터)
[00:30.00]<00:30.0>단어별 <00:30.7>하이라이트도 <00:31.6>가능
[offset:-300]                  ← 전체 자막 300ms 앞당기기
```

**가장 쉬운 방법 — 스튜디오에서 타이밍 잡기**

1. `가사` 탭 → 가사를 한 줄씩 붙여넣고 `줄 목록 만들기`
2. `▶ 재생` 후, 각 줄이 시작되는 순간 그 줄의 `지금` 버튼 클릭
3. `◀ ▶` 로 0.1초씩 미세 조정
4. `.lrc 내보내기` → `public/video/lyrics/` 에 저장 → `렌더러가 읽을 경로`를 그 파일로 지정

## 3. MP4로 렌더링

처음 한 번만 폰트를 받습니다 (Node 캔버스에는 한글 폰트가 없어 안 받으면 글자가 깨집니다).

```bash
npm run video:fonts      # assets/fonts/ 에 Noto Serif KR 등 다운로드 (약 24MB, git 제외됨)
```

렌더:

```bash
npm run video:render                                    # video.project.json 자동 사용
npm run video:render -- --project my.json --out out/a.mp4
npm run video:preview                                   # 640x360 / 15fps 빠른 확인
```

**검수용 옵션** — 5분짜리를 다 뽑기 전에 구도부터 확인하세요.

```bash
npm run video:render -- --still 42          # 42초 지점 한 프레임만 PNG
npm run video:render -- --contact-sheet     # 전체 타임라인을 4x3 썸네일 한 장으로
npm run video:render -- --duration 20       # 앞 20초만
```

| 옵션 | 설명 |
|---|---|
| `--project <path>` | 프로젝트 JSON (기본: 루트의 `video.project.json`) |
| `--out <path>` | 출력 경로 (기본: `out/<name>.mp4`) |
| `--preview` | 640×360 / 15fps / crf 28 |
| `--width <n>` | 가로 해상도 덮어쓰기 (세로는 비율 유지) |
| `--fps <n>` `--crf <n>` | 프레임레이트 / 화질 (낮을수록 고화질, 기본 18) |
| `--duration <sec>` `--start <sec>` | 길이 / 시작 지점 |
| `--still <sec>` `--contact-sheet` | 정지 이미지 검수 |
| `--no-audio` | 무음 렌더 |

출력은 **H.264 (yuv420p) + AAC 256k, faststart** — 유튜브에 그대로 올릴 수 있습니다.

### 왜 브라우저 녹화가 아니라 Node CLI인가

`MediaRecorder`로 캔버스를 녹화하는 방법도 있지만 이 파이프라인은 쓰지 않습니다.

1. **실시간 녹화가 아님** — 프레임 단위로 그려 ffmpeg에 밀어넣으므로, 무거운 프레임에서
   끊기거나 프레임이 드랍되지 않습니다. 4K도 시간만 더 걸릴 뿐 결과는 동일합니다.
2. **진짜 MP4** — 브라우저 MediaRecorder는 사실상 WebM만 뱉습니다. 여기선 H.264 + AAC입니다.
3. **결정적** — 몇 번을 돌려도 같은 파일이 나옵니다.

프레임은 PNG를 거치지 않고 RGBA 원본 버퍼를 그대로 파이프로 보냅니다 (인코딩 왕복 제거).

## 4. 성능

1080p 기준 대략 **30~50 fps로 렌더** — 5분(9,000프레임) 영상이 3~5분쯤 걸립니다.
4K는 픽셀이 4배라 그만큼 느려집니다.

느리면 이 순서로 줄이세요.

1. `--preview` 로 먼저 구도 확정
2. `효과 > 필름 그레인` 을 0으로 (전체 화면 합성이라 가장 비쌉니다)
3. `효과 > 보케 개수` 줄이기
4. `배경 > 블러` 는 성능에 거의 영향이 없습니다 (축소-확대 방식이라 오히려 값이 클수록 빠름)

## 자주 겪는 문제

| 증상 | 원인 / 해결 |
|---|---|
| 한글이 □□□ 로 나옴 | `npm run video:fonts` 실행 안 함 |
| 자막이 안 나옴 | `lyrics.lrcSrc` 경로 확인. CLI가 못 찾으면 경고를 찍고 자막 없이 진행합니다 |
| 자막이 음악과 어긋남 | `가사 > 전체 오프셋` 또는 `.lrc` 의 `[offset:]` |
| 사진이 안 보임 | 경로는 `public/` 기준 상대경로 (`images/1.webp`) |
| 영상이 음악보다 짧음/김 | `출력 > 영상 길이` 를 비우면 음원 길이를 그대로 씁니다 |
| LP 사진이 거꾸로 보임 | 계속 회전하기 때문입니다. `LP > 회전 속도` 를 0으로 하면 고정됩니다 |

## 프로젝트 JSON

`video.project.json` 은 스튜디오와 렌더러의 단일 계약입니다. 손으로 고쳐도 됩니다.
스키마와 기본값은 [`src/video/engine/config.js`](../src/video/engine/config.js) 에 주석과 함께
정의되어 있습니다. 구버전 파일도 `mergeProject()` 가 기본값과 병합해 열어줍니다.
