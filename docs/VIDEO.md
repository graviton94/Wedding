# 웨딩 플레이리스트 영상 만들기

청첩장 사진으로 유튜브 플레이리스트 스타일 영상을 만들고 MP4로 뽑는 도구입니다.

화면 구성은 **여섯 가지 레이아웃** 중에서 고릅니다. 아래는 그중 하나(3분할 LP)입니다.

```
┌──────────┬────────────────┬──────────┐
│          │      ◯         │          │
│  사진    │   회전하는 LP   │  사진    │   ← 좌우는 사진 순서대로 크로스페이드
│  (짝수)  │   (고정 사진)   │  (홀수)  │
│          │                │          │
├──────────┴────────────────┴──────────┤
│            흘러가는 가사 자막          │
└──────────────────────────────────────┘
```

- 중앙: 고른 사진 한 장이 원 전체를 채우고 시계 방향으로 천천히 회전 (은/금 톤암 포함)
- 좌우: 사진 목록을 짝/홀로 나눠 갖고 번갈아 크로스페이드 — 한 번에 한쪽만 바뀌어 차분합니다
- 하단: `.lrc` 자막이 음악에 맞춰 흐르고, 단어별 하이라이트(가라오케)도 됩니다
- 그 밖에: 블러 배경, 보케, 광선 누출, 필름 그레인, 진행 바, 인트로/아웃트로 타이틀

---

## 구조

핵심은 **렌더 엔진 하나를 웹과 CLI가 공유**한다는 점입니다.

```
src/video/engine/        ← 순수 캔버스 렌더 엔진 (DOM·Math.random 미사용)
   drawFrame.js            프레임 합성 진입점: drawFrame(ctx, scene, env, t)
   timeline.js             사진 슬롯 / 좌우 컬럼 타임라인 계산
   lrc.js                  LRC 자막 파서
   config.js               프로젝트 스키마 + 기본값
   layers/                 background · splitColumns · vinyl · lyrics · overlays

src/video/studio/        ← 웹 디자이너 (#/studio)
tools/video/render.mjs   ← Node MP4 렌더러
```

엔진은 `drawFrame(ctx, scene, env, t)` 하나로 호출됩니다. 같은 `(scene, t)`면 항상 같은 픽셀이
나오도록 만들어져 있어서(시드 기반 난수, 시간 기반 애니메이션만 사용) **스튜디오 미리보기가
곧 최종 mp4**입니다.

`env`만 환경별로 다릅니다.

| | 브라우저 | Node |
|---|---|---|
| 캔버스 | `document.createElement('canvas')` | `@napi-rs/canvas` |
| 이미지 | `new Image()` | `loadImage()` |
| 폰트 | index.html의 Google Fonts | `assets/fonts/*.ttf` 등록 |

## 컨셉 프리셋 (시안)

**화면 구조**(레이아웃) + 색 + 서체 + 효과를 한 묶음으로 바꿉니다. 스튜디오 `무드` 탭에서
누르면 바로 적용되고, 사진·음원·가사는 그대로 유지됩니다.

### 가사 중심 컨셉 — 가사가 주인공, 사진은 받쳐주는 역할

| 프리셋 | 구조 | 특징 |
|---|---|---|
| **Cinéma** 시네마 자막 | 2.39:1 풀블리드 + 하단 자막 | 사진이 가장 크게 보임. 영화 자막 위치 |
| **Marquee** 밤의 간판 | 가사가 화면 한가운데 | 글자 비중 최대. 사진은 거의 지워진 배경 |
| **Défilé** 흐르는 가사 | 세로 스크롤 목록 + 옆 사진 컬럼 | 앞뒤 가사가 같이 보임. 유튜브 가사 영상에 가장 가까움 |
| **Carte Postale** 엽서 | 기울인 사진 카드 + 옆 가사 컬럼 | 사진이 "화면"이 아니라 "물건"으로 보임 |
| **Duplex** 2단 | 위 사진(78%) / 아래 가사 패널 | 사진을 크게 쓰면서 글자가 안 겹침 |

전부 미드나잇 파리 톤(짙은 밤색 + 놋쇠빛, 낮은 채도)을 공유합니다.

### LP 컨셉 — 첫 번째 구성 (3분할 + 회전 LP)

| 프리셋 | 무드 | 영문 서체 | 특징 |
|---|---|---|---|
| **Minuit** 미드나잇 파리 | 짙은 남색 밤 + 놋쇠빛 조명 | Cormorant Garamond *Italic* | 가장 어둡고 깊은 톤. 얇은 레터박스 |
| **Salon** 촛불 살롱 | 코냑빛 실내, 따뜻한 세피아 | Cormorant Garamond | 가장 부드럽고 밝음. 보케 강함 |
| **Pluie** 비 오는 창가 | 채도 뺀 회청색, 극도로 절제 | Italiana (아르데코) | **3분할 없음** — 원 하나만. 자간 넓음 |
| **Bobine** 오래된 필름 | 바랜 아카이브 필름 | Marcellus | 굵은 그레인, 넓은 레터박스, 컬럼 간격 |

국문은 아홉 안 모두 **나눔명조**입니다. 시안 이미지를 뽑아 비교하려면:

```bash
npm run video:themes                       # 아홉 개 전부 + 비교 시트
npm run video:themes -- --at 62            # 62초 지점 화면으로
npm run video:themes -- --theme marquee    # 하나만
npm run video:themes -- --theme cinema,defile,duplex --sheet lyrics-first
npm run video:themes -- --lrc video/lyrics/my.lrc   # 실제 자막으로
```

결과물은 `out/theme-*.png` 와 비교 시트 PNG입니다.

### 레이아웃 직접 고르기

프리셋과 별개로 `layout` 값만 바꿔도 됩니다 (`video.project.json`):

```json
{ "layout": "defile" }
```

`cinema` · `marquee` · `defile` · `carte` · `duplex` · `vinyl3` 중 하나.
레이아웃별 세부 값은 `layouts.<이름>` 아래에 있고, 쓰지 않는 레이아웃의 값은 무시됩니다.

## 세로 사진 다루기

이 프로젝트 사진은 **17장 중 16장이 2:3 세로**입니다. 16:9 화면에 그냥 cover로
넣으면 배율이 2.4배까지 올라가 사진 세로의 1/4 남짓만 남습니다 — 머리도 발도 잘립니다.
그래서 채우는 방식(`fit`)을 레이아웃마다 고를 수 있게 했습니다.

| `fit` | 동작 | 언제 |
|---|---|---|
| **`width`** | **가로를 꽉 채우고, 넘치는 세로만큼을 노출 시간 동안 훑음** | **세로 사진 기본** (Cinéma, Marquee, Duplex) |
| `cover` | 상자를 꽉 채우고 넘치는 부분은 자름 | 상자가 세로로 길 때 (Défilé 컬럼) |
| `blur` | 사진 전체를 담고 남는 자리는 같은 사진을 크게 흐린 것으로 채움 | 사진 전체를 한 화면에 꼭 보여야 할 때 |
| `contain` | 사진 전체를 담고 남는 자리는 단색 여백 | 여백을 의도적으로 보여줄 때 |

**`width`가 영상에선 가장 낫습니다.** 상자에 사진을 맞추려 하지 말고 *시간*을 쓰는
방식입니다 — 가로가 꽉 차니 여백도 이음새도 없고, 한 컷엔 일부만 보이더라도
노출 시간 동안 사진 위→아래를 지나가며 결국 전체를 보여줍니다.

```
panStart 0.14  ─────▶  panEnd 0.86
   (상단 14%)           (하단 86%)
```

`panStart` / `panEnd`는 레이아웃별로도, **사진별로도** 지정할 수 있습니다.
인물이 위쪽에 몰린 컷은 범위를 좁게 잡으면 끝에서 치맛단만 남는 걸 피할 수 있습니다.

```json
{ "src": "images/3.webp", "panStart": 0.1, "panEnd": 0.55 }
```

가로 사진(`12.webp`)은 가로맞춤하면 위아래가 남으므로 자동으로 `cover`로 떨어집니다.

**화면 비율도 함께 고려하세요.** `6:4 (3:2) 1920×1280` 프리셋은 16:9보다 세로 여유가
커서 2:3 사진이 한 화면에 훨씬 많이 담깁니다. 가사 중심 컨셉 다섯은 이 비율이 기본입니다.

`blur`를 쓸 때는 사진 가장자리를 그라데이션으로 깎아 배경에 녹입니다 — 직선 경계가
드러나면 "사진이 화면에 안 맞는다"는 인상이 생기기 때문입니다.

> `15.webp`는 세 컷을 세로로 이어붙인 콜라주입니다. 어느 레이아웃에서도 어색하게
> 보이므로 목록에서 빼거나 세 장으로 나눠 쓰시길 권합니다.

## 2개 국어 자막 (영어 + 한국어)

`.lrc`에 **같은 타임스탬프로 두 줄**을 쓰면 위=원문 / 아래=번역으로 묶여 렌더됩니다.
이건 이중 언어 LRC의 사실상 표준 형태라, 밖에서 받아온 파일도 그대로 들어갑니다.

```lrc
[00:24.10]The English line goes here
[00:24.10]여기에 한국어 번역이 들어갑니다
[00:29.80]The next line
[00:29.80]다음 줄 번역
```

스튜디오 `2개 국어` 탭에서 조정할 수 있는 것:

- 번역을 위/아래 중 어디에 둘지 (`번역을 위로` — 국문을 크게 보여주고 싶을 때)
- 번역 글자 크기·투명도·줄 간격
- 원문 서체를 본문(국문 명조) / 강조(영문 이탤릭) 중 무엇으로 할지, 자간

> 번역이 붙으면 "다음 줄 미리보기"는 자동으로 꺼집니다 — 세 줄이 겹치면 산만해집니다.

> ⚠️ 상용 음원의 가사·번역을 넣어 공개 배포할 계획이라면 권리 확인이 필요합니다.
> 저장소에는 가사 텍스트를 포함하지 않습니다.

| 자막 스타일 | 글자 크기·위치·색·애니메이션·가라오케 |

## 2. 가사 자막 넣기

> ⚠️ 이 저장소에는 가사 텍스트를 커밋하지 않습니다. 직접 준비한 `.lrc`를 쓰세요.
> 영상을 공개 배포할 계획이라면 음원·가사의 이용 권리를 먼저 확인하시기 바랍니다.

`public/video/lyrics/sample.lrc` 가 문법 예시가 들어간 빈 템플릿입니다. 복사해서 채우세요.

```lrc
[00:12.40]가사 한 줄
[00:18.90]다음 줄
[00:24.00]                     ← 텍스트 없는 줄 = 간주 (음표 인디케이터)
[00:30.00]<00:30.0>단어별 <00:30.7>하이라이트도 <00:31.6>가능
[offset:-300]                  ← 전체 자막 300ms 앞당기기
```

2. `▶ 재생` 후, 각 줄이 시작되는 순간 그 줄의 `지금` 버튼 클릭
3. `◀ ▶` 로 0.1초씩 미세 조정
4. `.lrc 내보내기` → `public/video/lyrics/` 에 저장 → `렌더러가 읽을 경로`를 그 파일로 지정

## 3. MP4로 렌더링

처음 한 번만 폰트를 받습니다 (Node 캔버스에는 한글 폰트가 없어 안 받으면 글자가 깨집니다).

```bash
npm run video:fonts      # assets/fonts/ 에 폰트 다운로드 (약 28MB, git 제외됨)
```

받는 서체: Noto Serif KR, 나눔명조, Cormorant Garamond (로만+이탤릭),
Playfair Display, Italiana, Marcellus, Great Vibes.
브라우저는 `index.html`의 Google Fonts로 같은 목록을 불러오므로 미리보기와 최종물이 일치합니다.

렌더:

```bash
npm run video:render                                    # video.project.json 자동 사용
npm run video:render -- --project my.json --out out/a.mp4
npm run video:preview                                   # 640x360 / 15fps 빠른 확인
```

**검수용 옵션** — 5분짜리를 다 뽑기 전에 구도부터 확인하세요.

```bash
npm run video:render -- --still 42          # 42초 지점 한 프레임만 PNG
npm run video:render -- --contact-sheet     # 전체 타임라인을 4x3 썸네일 한 장으로
npm run video:render -- --duration 20       # 앞 20초만
```

| 옵션 | 설명 |
|---|---|
| `--project <path>` | 프로젝트 JSON (기본: 루트의 `video.project.json`) |
| `--out <path>` | 출력 경로 (기본: `out/<name>.mp4`) |
| `--preview` | 640×360 / 15fps / crf 28 |
| `--width <n>` | 가로 해상도 덮어쓰기 (세로는 비율 유지) |
| `--fps <n>` `--crf <n>` | 프레임레이트 / 화질 (낮을수록 고화질, 기본 18) |
| `--duration <sec>` `--start <sec>` | 길이 / 시작 지점 |
| `--still <sec>` `--contact-sheet` | 정지 이미지 검수 |
| `--no-audio` | 무음 렌더 |

출력은 **H.264 (yuv420p) + AAC 256k, faststart** — 유튜브에 그대로 올릴 수 있습니다.

### 왜 브라우저 녹화가 아니라 Node CLI인가

`MediaRecorder`로 캔버스를 녹화하는 방법도 있지만 이 파이프라인은 쓰지 않습니다.

1. **실시간 녹화가 아님** — 프레임 단위로 그려 ffmpeg에 밀어넣으므로, 무거운 프레임에서
   끊기거나 프레임이 드랍되지 않습니다. 4K도 시간만 더 걸릴 뿐 결과는 동일합니다.
2. **진짜 MP4** — 브라우저 MediaRecorder는 사실상 WebM만 뱉습니다. 여기선 H.264 + AAC입니다.
3. **결정적** — 몇 번을 돌려도 같은 파일이 나옵니다.

프레임은 PNG를 거치지 않고 RGBA 원본 버퍼를 그대로 파이프로 보냅니다 (인코딩 왕복 제거).

## 4. 성능

1080p 기준 대략 **30~50 fps로 렌더** — 5분(9,000프레임) 영상이 3~5분쯤 걸립니다.
4K는 픽셀이 4배라 그만큼 느려집니다.

느리면 이 순서로 줄이세요.

1. `--preview` 로 먼저 구도 확정
2. `효과 > 필름 그레인` 을 0으로 (전체 화면 합성이라 가장 비쌉니다)
3. `효과 > 보케 개수` 줄이기
4. `배경 > 블러` 는 성능에 거의 영향이 없습니다 (축소-확대 방식이라 오히려 값이 클수록 빠름)

## 자주 겪는 문제

| 증상 | 원인 / 해결 |
|---|---|
| 한글이 □□□ 로 나옴 | `npm run video:fonts` 실행 안 함 |
| 자막이 안 나옴 | `lyrics.lrcSrc` 경로 확인. CLI가 못 찾으면 경고를 찍고 자막 없이 진행합니다 |
| 자막이 음악과 어긋남 | `가사 > 전체 오프셋` 또는 `.lrc` 의 `[offset:]` |
| 사진이 안 보임 | 경로는 `public/` 기준 상대경로 (`images/1.webp`) |
| 영상이 음악보다 짧음/김 | `출력 > 영상 길이` 를 비우면 음원 길이를 그대로 씁니다 |
| LP 사진이 거꾸로 보임 | 계속 회전하기 때문입니다. `LP > 회전 속도` 를 0으로 하면 고정됩니다 |
